What you get

Six live metrics, a ranked process list, and an overlay that stays out of the way.

Live metrics

Processor, graphics, memory, disk and network, sampled every second with hand-drawn history graphs. Percentages are pinned to a real 0-100 scale rather than auto-fitted, so an idle machine looks idle instead of frantic.

Per-process GPU

Windows publishes GPU utilization for every process. Nocturne keeps that attribution and shows you which programs are actually holding the card - the number Task Manager buries and most overlays discard entirely.

Game overlay

One dim line of text above everything, including fullscreen-borderless games. Clicks pass straight through it and it never takes focus. Hold a hotkey and drag it anywhere; it remembers where, per display.

Plain-language answers

Rather than leaving you to interpret six graphs, Nocturne names the constraint: CPU-bound, GPU-bound, disk saturated, or memory nearly full - and which background programs are competing for it.

Lives in the tray

Closing the window doesn't quit; it keeps sampling from the notification area. Window position, overlay placement and preferences survive a restart, and are written a couple of seconds after they change - not only on exit.

One file

About a megabyte. No installer, no setup wizard, nothing written to Program Files or the registry beyond one optional startup entry you control. Uninstalling means deleting the file.

The difference

A number isn't an answer.

Knowing the GPU sits at 92% doesn't tell you what to do. Knowing that a browser you forgot about is holding 24% of it does.

Windows exposes one performance counter instance per GPU engine per process. Nocturne reads all of them, groups them by engine type, and joins the result with per-process CPU and the window you're actually looking at. That's the whole trick - the data was always there.

Processes you can't act on - the desktop compositor, the shell, Nocturne itself - are filtered out. Advice you can't act on is worse than silence.

Architecture, not marketing

What Nocturne will never do

These aren't features waiting to be built. They're decisions, and they're why the app can be small, safe beside anti-cheat, and auditable in an afternoon.

  • No process injection

    Nothing is loaded into another program's memory. The overlay is an ordinary always-on-top window, not something drawn inside your game. This is the single behaviour most likely to attract anti-cheat and antivirus attention, and it is the reason frame-rate measurement is still absent rather than shipped the easy way.

  • No kernel driver

    Every metric comes from a documented user-mode Windows API. That's also why CPU temperature and fan speed aren't here - reading them needs a driver, and a signed driver is a liability that a performance monitor shouldn't be asking you to accept.

  • No keyboard or mouse hooks

    Hotkeys use RegisterHotKey, which asks Windows to report a handful of specific chords and nothing else. A low-level hook would observe every keystroke on the machine. Dragging the overlay reads the cursor only while a drag is actually happening.

  • No network calls

    No telemetry, no update checks, no analytics. There's no code in the repository that opens a socket. Even Authenticode signature checks run with cache-only retrieval so that inspecting a file can't quietly cause an outbound request.

  • No elevation

    Runs as a normal user. It never asks for administrator, and the one optional setting that touches the registry - start with Windows - writes a single per-user value you can remove from Task Manager.

Every Windows API the app touches lives in one file, so the complete list can be read in a sitting: Nocturne.Core/Native/NativeMethods.cs

Where every number comes from

No vendor SDKs, no proprietary blobs. If you want to check a figure, this is what to check it against.

MetricSourceNotes
CPUGetSystemTimesIdle, kernel and user tick deltas. Kernel time includes idle - a detail that trips up most implementations.
MemoryGlobalMemoryStatusExComputed from byte totals rather than the rounded percentage, so the graph moves smoothly.
GPU\GPU Engine(*)\Utilization PercentageWorks on AMD, Intel and NVIDIA alike. Summed per engine type; the busiest type is reported, matching Task Manager.
Disk\PhysicalDisk(_Total)\Disk Bytes/secRead through PDH directly rather than the managed wrapper, which is slow to initialise.
NetworkSystem.Net.NetworkInformationByte deltas across active adapters, divided by measured elapsed time rather than the nominal interval.
ProcessesNtQuerySystemInformationOne call returns every process. The usual per-process approach is denied for protected processes without elevation and silently hides about half of them.

Provenance

Check the bytes yourself.

Releases are built by GitHub Actions from a tagged commit - never uploaded from a developer's machine. Each one publishes a SHA-256 next to the download and names the exact commit it came from.

So you don't have to take anyone's word for it. Read the source, read the build log, hash the file you downloaded, and confirm they agree.

Not yet code-signed, so Windows SmartScreen will warn about an unrecognised publisher. That happens to every new application until it builds reputation, and it's a fair thing to be cautious about - which is exactly why the checksum is there.

Getting started

  1. Install the runtime

    Nocturne needs the .NET 10 Desktop Runtime, a one-time install from Microsoft. Without it Windows shows a dialog with a download link instead of starting the app - that's expected, not a broken download.

  2. Download and run

    One Nocturne.exe. Put it anywhere - Desktop, a tools folder, a USB stick. There's nothing to install and nothing to configure before it works.

  3. Get past SmartScreen

    Until the project is code-signed you'll see an unrecognised-publisher warning. Choose More info -> Run anyway, ideally after checking the hash above.

  4. Find it in the tray

    Windows 11 hides new tray icons behind the ^ chevron. Drag the crescent onto the taskbar to keep it in view. Closing the window keeps it running there.
